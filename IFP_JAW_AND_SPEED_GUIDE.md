# Добавление движения челюсти и изменение скорости анимаций GTA San Andreas

## 1. Что именно изменяется

Анимации GTA San Andreas обычно хранятся в файлах IFP. Основные PED-анимации находятся в `ped.ifp`, а дополнительные группы могут быть вложены в `anim.img`, например:

- `PED / IDLE_chat` находится в `anim\ped.ifp`;
- `PED / endchat_01`, `endchat_02`, `endchat_03` находятся там же;
- `GANGS / prtial_gngtlkA-H` находятся в `gangs.ifp`, вложенном в `anim\anim.img`.

Движение челюсти задаётся отдельным треком кости:

```text
Name: Jaw
Key type: 3
Hierarchy ID: 8
```

Ускорение анимации выполняется не через отдельный параметр FPS. Нужно изменить временные метки всех ключей анимации.

## 2. Обязательная резервная копия

Перед любыми изменениями сохранить:

```text
anim\ped.ifp
anim\anim.img
```

Например:

```powershell
Copy-Item -LiteralPath '.\anim\ped.ifp' -Destination '.\anim\ped.ifp.bak'
Copy-Item -LiteralPath '.\anim\anim.img' -Destination '.\anim\anim.img.bak'
```

Нельзя считать файл исправным только потому, что скрипт завершился без ошибки. Повреждённый IFP иногда разбирается пользовательским скриптом, но вызывает вылет GTA SA или SA-MP.

## 3. Структура IFP ANP3

В GTA SA часто используется формат `ANP3`.

### Заголовок пакета

```text
Offset  Size  Назначение
0       4     Сигнатура ANP3
4       4     Размер данных после первых 8 байт
8       24    Имя группы
32      4     Количество анимаций
36      ...   Первая анимация
```

Поле по смещению `4` должно равняться:

```text
полный размер IFP - 8
```

### Заголовок анимации

Каждая анимация начинается с 36-байтового заголовка:

```text
Offset  Size  Назначение
0       24    Имя анимации
24      4     Количество треков костей
28      4     Общий размер данных ключей без заголовков треков
32      4     Флаг/версия анимации
36      ...   Первый трек
```

При добавлении нового трека нужно изменить оба поля:

1. Увеличить количество треков по смещению `+24`.
2. Увеличить размер данных ключей по смещению `+28`.

Если изменить только количество треков, файл может выглядеть читаемым в простом парсере, но быть некорректным для игры.

### Заголовок трека кости

Трек также начинается с 36-байтового заголовка:

```text
Offset  Size  Назначение
0       24    Имя кости
24      4     Тип ключей
28      4     Количество ключей
32      4     Hierarchy ID кости
36      ...   Ключи
```

Для трека `Jaw` из стандартных PED-анимаций:

```text
Тип ключей: 3
Hierarchy ID: 8
Размер одного ключа: 10 байт
```

Один 10-байтовый ключ состоит из:

```text
int16 quaternion_x
int16 quaternion_y
int16 quaternion_z
int16 quaternion_w
uint16 time
```

Кватернион хранится в сжатом виде. Для анализа его компоненты обычно делят на `4096.0` и нормализуют.

## 4. Выбор донора челюсти

Надёжные доноры:

- `PED / IDLE_chat`;
- `PED / endchat_01`;
- `PED / endchat_02`;
- `PED / endchat_03`.

У `IDLE_chat` трек `Jaw` имеет:

```text
Hierarchy ID: 8
156 ключей
Длительность: 207 временных единиц
Средний интервал: около 1.34
Амплитуда открытия: около 16 градусов
```

У `endchat_01` и `endchat_02`:

```text
61 ключ
Длительность: 120
Интервал: 2
```

У `endchat_03`:

```text
71 ключ
Длительность: 140
Интервал: 2
```

Для обычного разговора удобнее использовать `IDLE_chat`. Для короткого завершения разговора можно копировать соответствующий `endchat`.

## 5. Копирование Jaw в другую анимацию

### Шаг 1. Найти длительность целевой анимации

Длительность определяется максимальной временной меткой последнего ключа среди всех треков:

```python
target_end = max(track.last_key.time for track in animation.tracks)
```

Не следует определять длительность только по числу ключей: разные треки могут иметь разную частоту ключей.

### Шаг 2. Скопировать заголовок Jaw

Из донора копируется 36-байтовый заголовок, включая:

- имя `Jaw`;
- тип ключей `3`;
- hierarchy ID `8`.

После генерации ключей в поле `+28` записывается новое количество ключей.

### Шаг 3. Повторить движение до конца цели

Если донор длится `207`, фаза повторения вычисляется так:

```python
source_time = target_time % 207
```

Для каждой целевой временной метки выбирается или интерполируется ближайший ключ донора.

Простой вариант:

```python
source_index = min(
    range(len(donor_times)),
    key=lambda index: abs(donor_times[index] - source_time),
)
```

Затем копируются первые 8 байт ключа, содержащие кватернион, а в последние 2 байта записывается `target_time`.

### Шаг 4. Проверить последнюю временную метку

Последний ключ Jaw должен доходить до конца целевой анимации:

```text
Jaw.last_time == target_end
```

Если последний ключ отсутствует, нужно явно добавить ключ на `target_end`.

### Шаг 5. Обновить размеры

После добавления Jaw:

```text
animation.track_count += 1
animation.frame_data_size += jaw_key_count * 10
ifp.chunk_size = ifp_file_size - 8
```

Размер заголовка трека, равный 36 байтам, не входит в `frame_data_size` анимации.

## 6. Порядок каналов как в ENDCHAT

Рабочие `PED / endchat_01-03` используют следующий порядок:

```text
Spine1          ID 3
Neck            ID 4
Head            ID 5
L Clavicle      ID 31
L UpperArm      ID 32
L ForeArm       ID 33
L Hand          ID 34
L Finger        ID 35
L Finger01      ID 36
R Clavicle      ID 21
R UpperArm      ID 22
R ForeArm       ID 23
R Hand          ID 24
R Finger        ID 25
R Finger01      ID 26
Jaw             ID 8
```

Для полного повторения структуры ENDCHAT трек `Jaw` должен быть последним.

Однако одинаковая структура IFP не гарантирует одинаковое поведение в игре. Ассоциация анимации может иметь флаг partial и отдельные правила смешивания костей.

## 7. Изменение скорости анимации

### Ускорение по коэффициенту

Для ускорения в `2x` все временные метки делятся на `2`:

```python
new_time = round(old_time / 2.0)
```

Для замедления до `0.5x` используется та же формула:

```python
new_time = round(old_time / 0.5)
```

Общая формула:

```python
new_time = round(old_time / speed_multiplier)
```

Примеры:

```text
speed_multiplier = 2.0   в два раза быстрее
speed_multiplier = 1.25  на 25% быстрее
speed_multiplier = 0.5   в два раза медленнее
```

### Какие треки ретаймить

Нужно изменять временные метки всех треков одной анимации:

- тела;
- головы;
- рук;
- пальцев;
- бровей;
- Jaw.

Если ретаймить только часть треков, тело и лицо рассинхронизируются.

### Сохранение порядка времени

После округления несколько ключей могут получить одинаковое время. Нужно обеспечить неубывающий порядок:

```python
new_time = max(new_time, previous_time)
```

Если движок или редактор требует строго возрастающие метки:

```python
new_time = max(new_time, previous_time + 1)
```

Но второй вариант ограничивает максимальное ускорение: нельзя разместить 100 уникальных ключей в диапазоне из 50 временных единиц. В таком случае часть промежуточных ключей нужно удалить.

### Подгонка частоты под донора

Средний интервал ключей донора:

```python
donor_interval = donor_duration / (donor_key_count - 1)
```

Для `PED / IDLE_chat / Spine 1`:

```text
duration = 207
key_count = 175
interval = 207 / 174 = 1.189655
```

Если в целевом опорном треке 41 ключ:

```python
target_duration = round((41 - 1) * 1.189655)
```

Получится примерно `48` временных единиц.

После определения новой длительности общий коэффициент применяется ко всем трекам:

```python
scale = target_duration / original_duration
new_time = round(old_time * scale)
```

Нельзя независимо вычислять скорость каждого трека по его числу ключей. Это изменит относительный тайминг костей.

## 8. Работа с anim.img

`gangs.ifp` обычно вложен в `anim.img`. IMG содержит таблицу записей с:

```text
начальным блоком
количеством блоков
именем файла
```

Размер блока равен `2048` байтам.

### Безопасный вариант

Использовать проверенный IMG-редактор, который:

1. Извлекает `gangs.ifp`.
2. Заменяет файл внутри IMG.
3. Пересчитывает блоки и таблицу записей.
4. Перестраивает архив.

### Изменение на месте

Допустимо только если новый IFP помещается в уже выделенные блоки:

```python
allocated_size = block_count * 2048
assert len(updated_ifp) <= allocated_size
```

После записи остаток выделенной области заполняется нулями. Размер `anim.img`, начальный блок и число блоков должны остаться прежними.

### Чего нельзя делать

Нельзя просто вставить байты в середину IMG. Это сдвинет следующие файлы без обновления таблицы.

Нельзя добавлять новую копию `gangs.ifp` в конец IMG без проверки совместимости загрузчика и всех directory offsets.

### Работа через GTA-SA Crazy IMG Editor

Для ручной замены IFP в `anim.img` можно использовать:

```text
D:\02_GAMES\Моды и софт GTA SA\GTA-SA Crazy IMG Editor\GTA-SA Crazy IMG Editor.exe
```

Безопасный порядок работы:

1. Полностью закрыть GTA SA и SA-MP.
2. Сделать резервную копию `anim\anim.img`.
3. Открыть `anim\anim.img` в GTA-SA Crazy IMG Editor.
4. Найти нужную запись, например `on_lookers.ifp`, `riot.ifp` или `strip.ifp`.
5. При необходимости извлечь исходную запись для отдельной резервной копии.
6. Использовать команду замены существующей записи, а не добавлять вторую запись с тем же именем.
7. Выполнить сохранение или перестроение архива средствами редактора.
8. Повторно открыть архив и убедиться, что запись существует в единственном экземпляре и имеет ожидаемый размер.

Редактор должен сам пересчитать начальный блок, количество блоков и directory entry. После замены всё равно необходимо разобрать записанный IFP и проверить его ANP3-заголовок, размеры анимаций и Jaw-треки.

### Если Jaw работает только в PED

`ped.ifp` лежит отдельно, поэтому игра читает его непосредственно из каталога `anim`. Остальные библиотеки обычно читаются из `anim.img`. Возможна ситуация, когда Jaw работает в `PED`, но не работает в `ON_LOOKERS`, `RIOT`, `BSKTBALL`, `MISC`, `OTB`, `ROB_BANK` или `STRIP`, хотя изменённые IFP внутри архива структурно корректны.

Сначала нужно проверить:

1. Игра и SA-MP были полностью закрыты во время замены.
2. В `modloader` нет другой копии `anim.img` или одноимённых IFP.
3. Directory entry изменённого IFP указывает на правильные блоки.
4. В архиве нет второй записи с тем же именем.
5. Извлечённый из уже записанного `anim.img` файл содержит ожидаемый движущийся Jaw.

Если архив корректен, но игра всё равно использует старое содержимое, надёжный вариант — установить изменённые библиотеки как loose IFP через Mod Loader:

```text
Grand Theft Auto San Andreas\modloader\Jaw Animations\on_lookers.ifp
Grand Theft Auto San Andreas\modloader\Jaw Animations\riot.ifp
Grand Theft Auto San Andreas\modloader\Jaw Animations\bsktball.ifp
Grand Theft Auto San Andreas\modloader\Jaw Animations\misc.ifp
Grand Theft Auto San Andreas\modloader\Jaw Animations\otb.ifp
Grand Theft Auto San Andreas\modloader\Jaw Animations\rob_bank.ifp
Grand Theft Auto San Andreas\modloader\Jaw Animations\strip.ifp
```

Плагин `gta3.std.stream` перехватывает загрузку по имени файла и отдаёт loose IFP вместо одноимённой записи из `anim.img`. В проверенной конфигурации этот способ исправил ситуацию, при которой Jaw работал в `ped.ifp`, но игнорировался во всех изменённых библиотеках внутри `anim.img`.

После установки loose IFP игру необходимо полностью перезапустить: анимационные библиотеки кэшируются при запуске. Нельзя заменять их и проверять результат в уже работающей GTA SA или SA-MP.

## 9. Особенность GANGS / prtial_gngtlk

Название `prtial_gngtlk` указывает на partial-анимацию. Такая анимация смешивается с базовой PED-анимацией, а не обязательно заменяет её полностью.

Из-за этого возможна ситуация:

1. В IFP присутствует корректный `Jaw`.
2. Ключи имеют правильную амплитуду.
3. Hierarchy ID равен `8`.
4. Игра загружает анимацию без вылета.
5. Челюсть визуально не движется.

В таком случае причина находится не в ключах, а в правилах смешивания partial-анимации. Базовая PED-анимация может продолжать управлять Jaw или маска partial-анимации может исключать лицевые кости.

Перед дальнейшим редактированием нужно отличать две проблемы:

- `Jaw` отсутствует или имеет постоянные ключи;
- `Jaw` корректен, но игнорируется системой смешивания игры.

Добавление всё новых копий Jaw во второй ситуации не исправит результат.

## 10. Проверка результата

### Структурная проверка

Для каждой изменённой анимации проверить:

```text
имя анимации
количество треков
уникальность Jaw
тип Jaw = 3
hierarchy ID Jaw = 8
количество ключей > 1
амплитуда Jaw не равна нулю
последнее время Jaw равно длительности анимации
все timestamps находятся в диапазоне uint16
```

### Проверка размеров

Проверить:

```text
ANP3 size == IFP size - 8
animation frame_data_size == сумма размеров ключей всех треков
конец последней анимации == фактический конец IFP
обновлённый IFP помещается в IMG entry
IMG entry не перекрывает соседние записи
```

### Проверка движения

Для Jaw сравнить максимальный угол относительно первого ключа. Если максимальный угол близок к нулю, челюсть фактически неподвижна.

Для разговорного донора ожидается амплитуда примерно до `16°`.

### Проверка в игре

1. Полностью закрыть GTA SA и SA-MP до изменения файлов.
2. Записать обновлённые файлы.
3. Запустить игру вручную.
4. Проверить конкретную анимацию по имени.
5. При вылете сразу восстановить оба файла из резервной копии.
6. Если игра работает, но Jaw не двигается, исследовать partial blending, а не повторно переупаковывать IMG.

## 11. Рекомендуемый рабочий процесс

1. Сделать резервные копии `ped.ifp` и `anim.img`.
2. Извлечь и разобрать нужный IFP.
3. Найти Action по точному имени без учёта регистра.
4. Найти донорский `Jaw` по имени и hierarchy ID `8`.
5. Определить длительность целевой анимации.
6. Сформировать циклические ключи Jaw.
7. Обновить число треков, размер данных Action и размер ANP3.
8. Если требуется ускорение, одним коэффициентом изменить timestamps всех треков.
9. Выполнить структурную проверку файла в памяти.
10. Записать через временный файл и атомарную замену.
11. Повторно прочитать уже записанный файл и проверить структуру.
12. Для IFP из `anim.img` заменить существующую запись через проверенный IMG-редактор, например GTA-SA Crazy IMG Editor, и повторно извлечь её для проверки.
13. Если игра не применяет корректную запись из `anim.img`, установить изменённый IFP через Mod Loader как loose-файл.
14. Только после полного перезапуска вручную тестировать конкретную анимацию в GTA SA или SA-MP.

## 12. Готовый скрипт

В репозитории находится `add_ifp_jaw.py`. Он принимает донорский IFP, целевой IFP, путь результата и точные имена анимаций:

```powershell
python .\add_ifp_jaw.py .\ped.ifp .\gangs.ifp .\gangs_with_jaw.ifp `
  prtial_gngtlkA prtial_gngtlkB prtial_gngtlkC prtial_gngtlkD `
  prtial_gngtlkE prtial_gngtlkF prtial_gngtlkG prtial_gngtlkH
```

Скрипт:

- поддерживает ANP3;
- добавляет или заменяет существующий Jaw;
- помещает Jaw последним треком;
- повторяет цикл до конца длинной анимации;
- сжимает полный цикл открытия-закрытия для короткой анимации;
- обновляет размеры ANP3 и Action;
- проверяет timestamps и фактическую амплитуду движения;
- пишет результат через временный файл.

Для осознанной перезаписи исходного файла нужно передать одинаковые пути и `--in-place`. При этом рядом создаётся резервная копия `.bak`, если её ещё нет.
